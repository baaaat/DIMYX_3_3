# Consignes de maintenance

- Lire `README.md` et `docs/ARCHITECTURE.md` avant toute intervention.
- Ne pas modifier, reformater, découper ou renommer les fichiers `.pde` dans une tâche de documentation. Une évolution du code doit faire l’objet d’une demande explicite.
- Conserver le couple dossier `DIMYX_3_3` / sketch `DIMYX_3_3.pde` et les chemins des JSON tant que le chargement n’est pas adapté et validé.
- Ne pas remplacer les scènes ou la configuration matérielle par des données de démonstration.
- Documenter en français les comportements constatés ; distinguer les propositions des fonctionnalités existantes.
- Ne pas inventer de version de dépendance, de firmware ou de modèle de carte.
- Vérifier les différences Git et les liens documentaires. Pour une tâche documentaire, vérifier que les fichiers applicatifs restent identiques.
- Pour une évolution fonctionnelle, appliquer la validation manuelle de `CONTRIBUTING.md` et indiquer les vérifications qui n’ont pas pu être réalisées.
